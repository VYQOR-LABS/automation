Vico AI

Assistant for connected services

Conversations and information, brought together.

Vico AI is an AI-powered assistant designed to help users manage conversations and information across connected services. It can work with messaging and, when authorized, Google Calendar and Gmail to help retrieve relevant information and respond to requests.

Vico AI is an evolving backend service. Available functions depend on the operator’s configuration, connected accounts, and access controls.

How Vico AI works

Vico AI receives a message or API request, identifies supported tasks, and uses the configured AI provider to prepare a response. Where a request calls for connected information, the service can use an authorized integration to retrieve that information. The AI provider may receive the request and relevant results so it can produce a response.

The service is currently configured around one shared application-owner context and one shared Google account. It is not a consumer sign-up product with separate accounts and isolated data for each person.

Available capabilities

Implemented

WhatsApp messaging integration

The backend supports configured WhatsApp Business Platform webhook processing, outbound text and template messages, and message-template and phone-number management. Meta account setup, permissions, and eligibility are required.

Implemented

Google Calendar

After the account owner authorizes Google, the backend can look up events in the connected account’s primary Calendar. The OAuth service also requests permission to manage Calendar events; availability of event changes depends on the configured application workflow.

Implemented

Gmail and AI responses

The integration supports Gmail message search and retrieval, with Gmail sending implemented in the service layer. AI responses can use supported tool results and the AI provider configured by the operator. User-facing availability depends on the deployment.

Connected accounts and authorization

Google features require an account owner to complete Google’s OAuth consent flow. The current OAuth request asks for Calendar event access, Gmail read access, and Gmail send access. Vico AI stores OAuth tokens encrypted in its configured database and uses them to make authorized requests to Google. The connected Google account is shared by this application deployment.

WhatsApp features require the operator to configure a WhatsApp Business phone number, account identifiers, and credentials. WhatsApp webhook signatures authenticate the platform request; they do not prove that the sender is the owner or authorize access to private Google information.

Users should connect only accounts they own or are authorized to grant. Google access can be revoked in the Google Account’s third-party connections settings. Revoking access may stop Google features and does not by itself delete information already held by the service operator.

Current limitations and unavailable features

Important: The application currently has no built-in HTTP authentication for its general API routes and uses a shared owner context. The operator must restrict network access or provide an authentication boundary before exposing the deployment to users or the public internet.

  • Separate user accounts and per-user isolation for Google and assistant data are not currently available.
  • A self-service Google disconnect and data-deletion interface is not currently implemented.
  • General HTTP API authentication is not currently implemented by this application; deployment-level access controls are required.
  • Calendar event changes and Gmail sending exist in backend service code, but are not exposed as general user-facing API routes in the current backend. Do not assume those actions are available.

This page describes the implementation currently present in this repository, not a feature roadmap.

Do not use the Service for information or workflows that require account-level isolation, authentication, or retention controls that the operator has not independently configured.
