1. Important service and access notice

Vico AI is configured as a single-owner service. It connects to one shared Google account and uses a shared application-owner context. It is not currently designed to isolate Google Calendar, Gmail, or assistant data between individual people who can reach the deployment.

The application does not currently implement HTTP authentication for its general API routes. Depending on how it is deployed, a person who can reach those routes may be able to request or trigger access to the shared account. WhatsApp senders may also share the same owner context; a valid WhatsApp platform signature confirms the platform sent a webhook, not that the sender is the account owner. The operator must restrict the service to trusted users and networks or put an appropriate authentication and authorization layer in front of it. Do not expose an unprotected deployment to the public internet.

Only connect a Google account whose owner has authority to grant the requested access and understands that the integration is shared by this deployment.

2. Information we handle

The information handled depends on which integrations and features the operator enables and what people send to the service. It may include:

  • Messages and contact details: message text, sender phone number, delivery or platform identifiers, and information included in a WhatsApp message or API request.
  • Google account data: Calendar event details and Gmail message data retrieved in response to a request. Gmail search can return message identifiers, subject, sender, recipient, date, snippet, and message body text depending on the operation.
  • AI request data: the message being processed, relevant context returned by enabled features, and results from Calendar or Gmail tools used to answer the request.
  • Account and integration data: internal owner identifiers, integration status, granted Google scopes, and encrypted Google access and refresh tokens.
  • Action and approval data: the details needed to evaluate, approve, reject, or record certain Calendar and email actions, along with their status and audit metadata.
  • Technical and diagnostic data: request method and route, request timing, network address metadata, operation names, response status, error details, and service logs needed to operate and troubleshoot the application.

Please do not send passwords, payment-card security codes, authentication secrets, or other information that is not needed for the requested task.

3. Google API data

Google permissions and uses

When an operator connects a Google account, the authorization flow requests permission to manage Calendar events, read Gmail messages, and send Gmail messages. The OAuth scopes are calendar.events, gmail.readonly, and gmail.send. Offline access lets the service refresh access credentials without asking the account owner to authorize every request.

We use Google API data only to provide and maintain the user-facing features requested through this service, such as finding Calendar events, looking up Gmail messages, and carrying out permitted actions. We do not use Google API data for advertising, sell it, or use it to build advertising profiles. Access is limited to the scopes granted by the account owner and to the application features that use them.

Token storage and handling

The service encrypts access and refresh tokens with AES-256-GCM before storing them in its PostgreSQL database. The encryption key is configured separately by the operator. Tokens are decrypted in application memory when needed; the Google API client uses the access token to authenticate requests to Google. The service refreshes expiring access tokens and saves updated credentials. Tokens and OAuth authorization codes are not returned in the OAuth callback response. Operators must protect both the database and the encryption key; encryption does not protect data from a compromised running application or an operator with access to the key.

Google API Services User Data Policy

Our use and transfer of information received from Google APIs will comply with the Google API Services User Data Policy, including its Limited Use requirements. Google API data is not sold or used for advertising. It is accessed and transferred only as needed to provide or improve user-facing features, for security and abuse prevention, to comply with applicable law, or with the account owner’s consent.

4. How information is used

We may use information to:

  • receive and respond to messages and service requests;
  • retrieve relevant Calendar events or Gmail messages from the connected Google account;
  • generate an assistant response using the AI provider selected by the operator;
  • send messages or perform supported Calendar and email actions when requested and permitted;
  • apply configured approval checks to higher-risk actions, such as changing or deleting a Calendar event or sending sensitive email;
  • secure, monitor, troubleshoot, and maintain the service; and
  • meet legal obligations and respond to valid legal requests.

AI-generated responses can be inaccurate or incomplete. A response is not professional legal, medical, financial, or other regulated advice. Review information and proposed actions before relying on them.

5. How information is shared

Information may be processed by the following services when needed to provide the requested feature:

  • Google: OAuth token exchange and refresh requests go to Google. Calendar and Gmail requests are sent to the Google APIs using the connected account’s authorization.
  • WhatsApp/Meta: when the WhatsApp integration is enabled, message content and delivery information are exchanged with the WhatsApp Business Platform and Meta Graph API.
  • The configured AI provider: the assistant sends the current request and, where relevant, selected context and tool results to the provider selected by the operator. The available choices include OpenAI and Ollama. Ollama may run locally or at an operator-configured remote address; a remote Ollama deployment can be operated by a separate organization. The provider’s own privacy terms and configuration govern its processing.
  • Service infrastructure: the operator’s database, application host, and logging systems process information needed to run the deployment. The operator should identify its actual hosting providers and their locations in this policy before publication.

We do not sell personal information. We do not disclose Google API data to an AI provider for advertising. Where a user asks the assistant to answer using retrieved Google information, relevant request context and tool results may be included in the AI-provider request so it can produce a response. Check the selected provider and its data terms before using the service with sensitive information.

Information may also be disclosed where required by law, to protect the rights and safety of people or the service, or as part of a business reorganization with appropriate safeguards.

6. Retention and deletion

Information is kept for as long as it is needed to operate the service, maintain the connected integration, complete or audit an action, resolve disputes, comply with law, or protect the service. Actual retention periods depend on the operator’s database, log, hosting, and backup configuration.

The application does not currently provide a self-service account deletion or Google disconnect endpoint, and the code does not establish a general automatic deletion schedule for stored records. Do not assume that deleting a message, revoking Google access, or disconnecting a platform automatically deletes information already stored in the application database, logs, or backups. The operator must have a process to locate and delete eligible data and should state its real retention periods here before publication.

Revoking access in your Google Account stops future API access after the revocation takes effect, but it does not by itself erase tokens or other data already held by the service operator. Contact the operator to request deletion of stored integration data.

7. Security

The application encrypts Google OAuth tokens at rest in the database and uses a state value protected by a short-lived HttpOnly cookie to protect the OAuth callback. Logs are designed to record operational metadata rather than message or Calendar contents. Diagnostic logging may include request and error metadata; access to logs, databases, backups, application hosts, and encryption keys must be restricted and monitored by the operator.

No method of storage or transmission is completely secure. The application currently lacks built-in authentication for general HTTP API endpoints, so access restrictions at the network or deployment boundary are essential. Do not treat OAuth state protection as API authentication.

8. Your choices and privacy rights

  • Google permissions: review or revoke the application’s access in your Google Account security settings. Revocation may stop Calendar and Gmail features.
  • WhatsApp: stop sending messages to the connected business number to stop initiating new WhatsApp requests. This does not erase prior records.
  • AI processing: the operator can configure the AI provider. Ask the operator which provider is active before sending sensitive information.
  • Requests: depending on your location, you may have rights to access, correct, delete, restrict, or object to certain processing, or to complain to a data protection authority. Contact the operator using the details in the Contact section. We may need to verify your identity and may be unable to fulfill a request where an exception applies.

The service is configured around a shared account and does not currently provide user-level controls for separating one person’s access from another. The operator should not use it to process data where that shared model is incompatible with applicable privacy obligations.

9. Children’s privacy

The service is not designed for children and is not intended to collect children’s personal information. If you believe a child has provided information to the service, contact the operator so the issue can be reviewed and appropriate steps considered.

10. International processing

The operator, Google, Meta, the configured AI provider, and infrastructure providers may process information in countries other than the country where it was collected. The operator should identify its actual provider locations and the safeguards it relies on for international transfers before publication. Applicable local law may provide additional rights.
